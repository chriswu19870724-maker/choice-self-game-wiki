# 选择成就真我：游戏概念与设计记录

> 本文是项目的持续更新版共识文档。每次讨论后更新“当前共识”“待验证问题”和“决策记录”；保留重要变更的时间、理由与影响，避免把灵感或假设误当成已定案设计。
>
> **状态：** 概念探索 / 首个可玩切片定义中

> **最近整理：** 2026-11-10

## 一句话概念

一款以“选择成就真我”为内核的开放探索型叙事游戏。玩家通过行动和抉择，逐渐发现并捍卫自己想成为的人；世界会记住这些行动，但不替玩家指定唯一的政治或道德正确答案。

## 当前共识

### 核心体验

- 让玩家通过自己的选择形成身份，而不是先被一个固定职业、阵营或道德标签定义。
- 选择应带来可感知的后果，影响人物处境、世界状态、信任与未来机会；不简单标注“善／恶”或公布唯一正确路线。
- 让世界对玩家的行动有所记忆，同时容纳多种活法。天道、自然边界、因果与实际代价可以促使玩家思考，但不成为说教式判官。
- 支持不同动机与节奏：强杀、轻松探索、追逐欲望或财富、行侠仗义等路线都可能成立，并面对各自的后果。

### 题材与体验形态

- 当前优先考虑武侠／仙侠作为题材外壳；“选择成就真我”的内核应能迁移到其他题材。
- 以单机叙事体验为主，弱社交作为辅助；不以强 MMO、强制公会或开放世界阵营大战为方向。
- 不同题材可拥有不同的玩法模块，但应服务于同一核心：玩家能通过选择、行动和承担后果，活成自己选择的人。

### 武侠／仙侠玩法素材池

可探索的系统包括功法、斗技、灵宝、丹药、灵宠，以及赌场、炼丹、挖矿、采集、铸造等。它们是可选模块，不代表首版都要实现。

### 角色与社交设想

每位玩家可以创建一个持续成长的 Agent 角色，并赋予出生偏好与初始记忆；角色不应只是编号或固定脚本，而会因经历发展。玩家可能遇到其他玩家的 Agent，在线或离线互动、建立关系，并在共同经历后发展出伙伴关系或出战协作。

关系不应退化为好友列表、单一好感度数值，或“刷满亲密度就服从”的开关。是否信任、合作或并肩作战，应能体现双方经历、处境与选择。以上属于长期方向，尚未进入首个切片范围。

## 灵感来源与借鉴重点

| 作品 | 当前讨论中的灵感方向 |
| --- | --- |
| 《魔兽世界》 | 开放探索、PK、副本，以及地图编辑式闯关带来的探索与挑战空间 |
| 《烟雨江湖》 | 剧情厚度与武功系统 |
| 《仙逆》《斗罗大陆》 | 修炼过程与力量成长设定 |
| 《Undertale》 | 选择会影响剧情、世界状态与玩家发现的体验 |

这些是体验灵感，不是照搬清单；具体借鉴方式仍需逐项设计和验证。

另整理了[炼丹原型灵感研究](docs/alchemy-prototype-inspirations.md)，比较《Potion Craft》《炼金工房》《天国：拯救》《上古卷轴5：天际》等游戏机制，以及《斗破苍穹》《凡人修仙传》的炼药叙事。本轮认可的总体方向是参考药剂工艺：**先让基础合成可完成，再围绕基础结果持续优化**。这不代表具体操作、优化项目、解锁节奏或数值已定案；研究中的其他做法仍属候选灵感，尤其小说提供的是人物目标与资源压力，不是现成的游戏操作系统。

## 首个可玩切片：药铺炼丹

### 场景设想

神医离世后，普通炼丹弟子成为其唯一传人，经营一间药铺。玩家学习基础丹方，为前来求药的人炼丹；来客带来收入，也可能带来稀有药材、奇遇与线索。

炼丹可作为逐步解锁的技能：先让基础合成能够完成，再持续优化炼制结果；入门阶段可考虑丹胚、凝丹等简化前置过程，让玩家用短操作影响成丹结果，之后再逐步开放更复杂的炼丹体系。具体交互、优化方向与解锁节奏仍待验证，不让长期扩展妨碍首版聚焦于最小体验验证。

首个 Demo 的空间范围进一步聚焦为一间药铺：暂不依赖多地图跑图或宏大场景，优先在店内完成来客互动、问诊与线索观察、药材取舍和炼制操作。可参考用户分享的《深空当铺：可能是偷的》店内画面，将来客、柜台、库存与工作台集中到同一空间；参考的是空间组织，不是照搬规则。当前原型以三个交互区组织流程，V2.5 基线已由制作人冻结；见[药铺单场景探索与交互草案](docs/pharmacy-single-scene-exploration.md)和[药铺 V2.5 原型范围与交付要求](docs/pharmacy-prototype-plan-2026-11-10.md)。

### V2.5 原型基线（制作人已冻结）

- H1–H3、问诊和账本均可跳过；选方案前可回访线索。求药者／线索阶段不显示炉温或控火尺，观察不同身体部位后增加简短反馈；具体表达按冻结状态文档。
- 药柜账本在选方前呈现稀缺药的机会成本，并以警示或高亮突出关键药材库存；警示阈值与视觉样式仍待测试。
- 未选方案时进入炼制台只提示“先选方案”，不开放控火。选方后可返回 S2 改方；控火中可取消并返回 S2 改方，S3 两个返程口按冻结状态图实现。
- 控火滑块往返并逐渐加速，火焰随读数变化并配有简短旁白；只有玩家点击“收火”时判定，不自动收火。命中目标温区优化药效／节材；失手仍产出基础药并完成救治。
- 最终交药前的所有阶段均不扣库存，只在交药时结算。V2.5 不扩剧情分支、不制作正式美术；正式首次玩家测试招募继续暂停。

### V2.6 问询阶段增补（制作人已定范围）

为回应问询阶段“流程顺但可玩性趣味性不足”的反馈，制作人确认增加两组可选追问（关于手抖何时开始、离矿休息后的感受）；原话见[魏槐求药 V2.6 问诊增补](docs/wei-huai-quest-script-draft.md)。每问后可「继续问」或「去选方案」；问询可跳过，问 0／1／2 个不同问题都可选方案，未问项优先高亮，已问项可重复并得到同一回答。只记录是否问过，不改线索计数、库存、诊断、方案或控火状态；不暗示病因或标准答案、不加剧情支线。此为已定范围，已实现；最新全流程内部验收暂不通过：`1280×649` 桌面实测的四种救治组合及交药结算通过，但复查后回到「回顾已聊内容」页缺少直达已备成药入口，经「去选方案」绕回不符合要求。该修正不重炼、不扣库存，修复后复测此返程边界。H3 未获可确认反馈，不记通过；本轮不算 `390×844` 手机整体验收，首次玩家测试尚未进行。详见[药铺 V2.6 计划](docs/pharmacy-prototype-plan-2026-11-10.md)与[今日历史记录](history/2026-11-10.md)。

滑块速度与加速曲线、目标温区、旁白与局部反馈文案、库存警示阈值及命中后的优化幅度仍是 V2.5 的**待测参数**，不改变其冻结流程。本方案尚未通过正式玩家测试；本轮内部走查仅属部分走查，尚未通过完整手机验收（详见下文）。实现按 V2.5 冻结状态文档及上述 V2.6 问询增补执行，不再增加其他范围。

### V2.5 走查进展（2026-11-10）

> **状态：部分走查，尚未通过完整手机验收。** 策划当时实际视口为 `1280×649`，不是 `390×844`。另观察到窄高窗口中方案标题和底部返回按钮有裁切；因尚未在明确的 `390×844` 视口验收，不能据此判定为手机布局问题，也不能记录手机通过。首轮 `internal server error` 属测试中断，原因未知；没有证据表明是原型故障。

本轮已观察到：急治在 64°C 命中并完成交药，稀缺药库存从 1 扣至 0；跳过线索、问诊和账本的缓治在 38°C 失手，但基础药仍完成救治，库存只在交药时扣除。控火中取消后可返回 S2 改方且库存未变；H1–H3 实际点击成功，线索回应自然；控火滑块、火焰和旁白让操作更有参与感。

**待修项与节点：**（1）缓治选方后若宁神草缺货，当前提示不醒目且确认按钮灰置易让人误以为卡住；改为醒目提示“宁神草缺货，先选甘草替代”，并让按钮文字明确写出下一步动作。（2）收火后的成丹可视反馈偏弱；增加简短形成反馈并区分命中／失手，沿用灰盒素材，不扩剧情、不制作正式美术。美术原画承诺于 **2026-11-11 16:00（香港时间）前**交付这两项修正。

修正交付后，由策划在明确的 `390×844` 视口重走急治、缓治、跳过线索的缓治、热点真实点击及取消控火后改方；在此之前不得记录完整手机验收通过。详见[药铺 V2.5 原型范围与交付要求](docs/pharmacy-prototype-plan-2026-11-10.md)。

### 最小 Demo 范围

- 一间药铺作为主要、尽量唯一的实体场景；店内通过人物、物件与状态变化承载互动，首版不以多地图跑动为前提。
- 一位主要的求药者。
- 一张基础丹方。
- 少量药材，其中有一味稀缺药材。
- 一种玩家可理解、可操作的短炼丹过程；先完成基础合成，再验证持续优化的空间。可从丹胚、凝丹等简化环节入手；具体优化项未定。
- 一个会改变后续情境的关键选择。

### 候选草案：魏槐求药

魏槐求药流程见[V2.5 基线与 V2.6 问诊增补](docs/wei-huai-quest-script-draft.md)：两种治疗方案均有效，漏看线索或控火失手都不阻断基础救治。病因（包括矿尘等可能性）与具体药材功效仍未定案；原型及其反馈尚无玩家验证结果。

稀缺药留作修习／考核或出售周转的机会成本只作账面信息，选方前可见；最终交药前的所有阶段均不扣库存，只在交药时结算。旧的约 5 人试玩目标已暂停；正式首次玩家测试招募按用户决定暂不开展。

灰盒 V1 仅为此前的视觉布局基线；交互实现以新冻结的 V2.5 流程为准，尤其不得在最终交药前扣除库存。V2.5 继续不做正式美术。

## 核心权衡

首轮不把稀缺药的所有用途都做成剧情分支，而是聚焦两种都有效的治疗方案：急治使用稀缺药，缓治使用常见药并多休息一晚。用药库存、账本和休息时间呈现具体代价；修习／考核与卖药周转仅作为稀缺药被放弃用途的账面提示。

### 后续恢复玩家测试后需要验证

1. 玩家实际看到了哪些线索，漏看后是否仍能继续基础救治？
2. 玩家选方前是否看见稀缺药机会成本，选后是否读懂状态反馈？
3. 三个交互区可跳过、回访及按 S3 两个返程口返回 S2 的流程是否清楚？
4. 加速滑块、火焰变化、“收火”判定和旁白是否带来趣味与掌控感；失手后是否理解基础救治仍完成？
5. 两种治疗方案都有效的前提下，差异与可见后果是否清楚？
6. V2.6 的两组可选追问是否增加问询趣味性，同时保持可跳过、不暗示病因且不改变其他状态？

正式首次玩家测试招募目前暂停，以上问题是未来恢复测试时的验证项，不表示已开始招募或已有测试结论。具体速度、温区、文案、警示阈值与优化幅度仍待测。

### 首版明确暂缓

多人互动、AI 伙伴、完整拍卖行、大量丹方与药材、庞大开放世界、强 MMO 结构等，先留作未来扩展方向。只有当切片验证了核心体验后，再决定是否投入。

## 设计边界与原则

- **先验证核心，再扩展内容：** 首版只实现回答关键体验问题所需的最小范围。
- **选择必须有后果，但不必有标准答案：** 让玩家看到代价和影响，不用善恶分数取代理解。
- **世界记得行动：** 后续机会与关系应能回应玩家此前的行为。
- **系统服务于角色表达：** 经济、炼丹、战斗、社交等模块不能只为堆量，应支持玩家选择如何生活。
- **社交自愿且有情境：** 先不把公会、组队或持续在线作为主要进程门槛。
- **可迁移的内核，题材化的模块：** 保留核心体验，允许不同题材采用不同玩法系统。

## 待验证问题

- 入门炼丹的短操作如何表现丹胚、凝丹等过程？玩家操作如何影响结果，之后如何逐步解锁更复杂体系？
- 库存／账本如何清楚呈现稀缺药的被放弃用途，而不把它们扩成首轮剧情分支？
- 如何让玩家在选方前看到机会成本、选后读懂状态反馈，同时在交药前仍可改选？
- 稀缺药材从何而来，玩家何时获知其价值与限制？
- 求药者的需求、困境与信息应如何呈现，才能避免选择像纯粹的“资源计算题”？
- 如何让一间药铺在不依赖地图跑动的情况下保持可探索感；哪些店内物件与阶段变化能支撑问诊、调查、操作和后果反馈？
- 魏槐首轮原型中的线索、两种治疗方案、短控火和可见代价是否易懂；哪些内容需在试玩后调整？
- 选择后果如何延续到下一次游玩或后续章节，同时让因果可理解？
- Agent 的出生偏好、初始记忆与成长如何表达，才能形成角色个性，而不是随机标签？
- 在线／离线互动与好友、伙伴关系如何保护玩家自主性，不演变为刷数值或强制社交？
- 如何在不判定唯一政治或道德答案的前提下，让世界边界、自然规律与行动代价保持可信？

## 如何继续滚动更新

1. 每次讨论后先更新上面的“当前共识”与“待验证问题”，只把明确形成的结论写成共识。
2. 对方向变化，在“决策记录”新增一行，简记日期、结论及状态；如有重要取舍，补充理由和受影响的章节。
3. 保留仍有效的历史记录，不用新结论静默覆盖旧决策；必要时标注“已被后续决策取代”。
4. 将新机制或灵感标为“候选／待验证”，不要提前写成已经承诺的功能。
5. 进入切片制作后，可新增独立的 `docs/` 文档记录流程图、数值、任务拆分或测试反馈，并在此页链接。
