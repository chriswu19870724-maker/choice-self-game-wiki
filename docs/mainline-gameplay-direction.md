# 当前主线玩法方向：铸剑—遣徒—历练—再铸

> **状态：当前主线方向，更新于 2026-11-13。** 本文记录已明确的主线关系与首切片边界；第二份方案中未被明确采纳的系统、规则和数值仍是提案，不自动成为承诺。

## 为什么切换主线

此前完整架构方案以铸剑、交易和资产成长构成经营循环。当前决定改以《铸剑山庄弟子历练玩法改造方案》为主线，让剑、弟子和历练风险彼此牵连；旧架构留作参考，药铺原型转为旧验证分支。

当前循环不是单向生产与出售，而是：

**手动铸剑 → 选择弟子与历练地 → 在可读风险下做节点抉择 → 收获／损失 → 再铸。**

## 循环中的玩家体验

1. **手动铸剑。** 玩家亲手完成一把剑；锻造操作与剑的表现如何关联仍待原型验证。
2. **选择弟子与历练地。** 玩家派出一名具名弟子，并选择一个历练地点。首个切片不需要大规模弟子池或多张地图。
3. **阅读风险并做节点选择。** 历练由可读的风险信息与连续节点选择构成，不是点击派遣后等待，也不应把关键结果藏在黑箱概率中。节点具体类型、每个选项数量及风险表达仍待设计。
4. **承担结果。** 玩家获得收获，或面对剑与弟子的损失；至少要让切片呈现一次失败。具体损失模型尚未确认。
5. **再铸。** 失败后进入重铸，使玩家有机会从结果回到铸剑环节。重铸要消耗什么、失败资源能否回收、是否保留其他进度，均待验证。

## 首个垂直切片的边界

**已确认范围：**

- 一把剑；
- 一名具名弟子；
- 一个历练地；
- 3–5 个历练节点，并在可读风险下作选择；
- 一次失败后的重铸；
- 完整表达“手动铸剑 → 派遣与节点抉择 → 收获／损失 → 再铸”的核心循环。

首切片先回答玩法是否成立，不以完整山庄经营、拍卖、榜单、四条成长路线或长线剧情为前置条件。若实现时发现某项内容不是验证该循环所必需，应优先保持切片边界。

## 已确认的开发引擎方向

制作人已明确选择 **Godot** 作为本项目开发引擎。此决定仅确定引擎选择；Godot 具体版本、渲染器、目标平台与导出矩阵均保持未决定。不得据此推断其他实现架构，也不涉及生产代码变更。

## 提案细节与当前边界

第二份方案包含大量可供讨论的细节，例如剑品等级、弟子五维、成功率表、期望值、剑冢与传承、路线定位、建筑和长时长成长节奏。这些内容仍需逐项判断，不因被写入方案就自动成为当前已定规格。

尤其以下内容**不直接锁入 MVP**：

- 四条流派／四流派完整内容；
- 永久死亡或不可回滚的死亡规则；
- 20 小时内容目标；
- 具体成功率、死亡率、风险档位或概率公式；
- 大规模弟子池、完整经济与山庄经营系统。

风险必须可读是当前方向要求；风险概率、收益倍数及玩家接受度阈值则仍属待验证假设。MVP 是否出现死亡、何种损失可承受，需基于原型证据另行决策。

## 待决策事项

1. 锻造的具体操作与时长，以及锻造技术如何影响剑在历练中的表现。
2. 一个历练地点的主题、环境信息和可读风险项。
3. 3–5 个节点的构成、分支方式、每个选项的代价与信息披露。
4. 失败时剑、弟子与材料分别会发生什么；重铸成本如何设定。
5. 具名弟子在切片中如何表现个性与关系重量，哪些成长数值可省略。
6. 以何种观察或玩家测试判断循环成立；数值目标与验收门槛尚未确认。
7. 通过验证后，是否扩到流派、永久死亡、剑冢传承或更长时长内容。
